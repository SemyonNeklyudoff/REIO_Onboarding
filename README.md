# REIO Onboarding

Готовое отдельное приложение на **Expo + React Native + TypeScript**: краткий онбординг из **7 страниц**, финальный экран и подробная инструкция по функциям REIO. Акцентный цвет — `#395CF5`.

## Подключение через Codex

1. Скачайте репозиторий: **Code → Download ZIP** и распакуйте, либо выполните:

   ```sh
   git clone https://github.com/SemyonNeklyudoff/REIO_Onboarding.git
   ```

2. Откройте в Codex **проект основного приложения**, в которое нужно встроить экраны. Дайте Codex доступ к папке `REIO_Onboarding` (например, добавьте её в доступное рабочее пространство или укажите абсолютный путь).
3. Скопируйте **весь блок ниже** кнопкой копирования в его правом верхнем углу, вставьте в чат Codex и отправьте. Промпт просит выполнить интеграцию и проверки; доступ к исходникам и подходящие средства сборки должны быть доступны разработчику. Для SwiftUI потребуется нативный перенос, для React Native — подключение готовых модулей.

Тот же текст без Markdown-обёртки: [INTEGRATION_PROMPT.md](INTEGRATION_PROMPT.md).

## Посмотреть приложение отдельно

Нужны Node.js 22.14+ и npm. Версии зависимостей зафиксированы в `package-lock.json`.

```sh
cd REIO_Onboarding
npm ci
npm start
```

В терминале Expo нажмите `i` для iOS Simulator или `a` для Android Emulator; соответствующий SDK и симулятор должны быть установлены. Для Expo Go нужна версия с поддержкой SDK из `package.json`. Это исходники приложения, а не готовый установочный IPA/APK.

## Состав экранов

| № | Экран | Содержимое |
|---|---|---|
| 1 | Приветствие | Обновлённое приложение, мокап Главной |
| 2 | Главная | Коммунальные расходы, документы, показатели |
| 3 | Мои номера — список | Поиск и список помещений |
| 4 | Мои номера — карточка | Чат с УК, заявки, документы и аналитика |
| 5 | Коммунальные услуги — история | Вкладки «Ждёт оплаты / Оплачено», статусы |
| 6 | Коммунальные услуги — детализация | Состав начислений перед оплатой |
| 7 | Настройки | Тема, язык, push/email |

После семи страниц идёт отдельный финальный экран с иллюстрацией и кнопками «Начать пользоваться» / «Посмотреть ещё раз». В демо он открывает раздел «Ещё»; пункт «Инструкция» ведёт к семи темам подробной справки с поиском. Демонстрационная кнопка «Выйти» запускает обзор заново; в реальном приложении сохраняется штатный выход из аккаунта.

Анимации конечные, используют native-driven transform/opacity и учитывают Reduce Motion и уход приложения в фон. Мокапы растворяются в белый градиент снизу. Основной текст поддерживает увеличение шрифта, при нехватке места доступна прокрутка. Иллюстрации содержат примеры данных и не выполняют реальные операции.

## API для React Native

Переносите `src/onboarding/` целиком с ассетами; для подробной инструкции также `src/guide/`. В RN-модулях используются React, React Native, `react-native-svg` и `react-native-safe-area-context`. В Expo установите совместимые версии:

```sh
npx expo install react-native-svg react-native-safe-area-context
```

В bare React Native установите совместимые пакеты и выполните штатную настройку iOS pods. Не переносите версии Expo/RN или lockfile этого превью поверх существующего приложения.

```tsx
import { Onboarding, OnboardingCompletion } from './src/onboarding';
import { GuideScreen } from './src/guide/GuideScreen';

// Обработчики реализует принимающее приложение.
<Onboarding onComplete={finishOnboarding} onSkip={skipOnboarding} />
<OnboardingCompletion onStart={openMainApp} onReplay={replayOnboarding} />
<GuideScreen onBack={openMoreSection} />
```

Это три разных маршрута, а не одновременное отображение. `SafeAreaProvider` должен быть выше в дереве. Отключите дублирующий header навигатора. Завершение и пропуск обрабатываются один раз на экземпляр `Onboarding`; при повторном просмотре смонтируйте новый экземпляр. Хранение версии прохождения и навигацию подключает основное приложение — в демо состояние находится только в памяти и обзор начинается заново при перезапуске.

Для SwiftUI прямой импорт TSX невозможен: используйте нативные компоненты и ассеты принимающего приложения, сохраняя вид и поведение. Готового Swift-пакета в этом репозитории нет.

## Где редактировать

- `src/onboarding/content.ts` — актуальные тексты семи страниц.
- `src/onboarding/scenes/index.ts` — их порядок и компоненты.
- `src/onboarding/scenes/PhoneMockupScene.tsx` — общая рамка и градиент мокапов.
- `src/onboarding/assets/` — изображения, включая предоставленные скриншоты.
- `src/onboarding/motion.ts`, `useMotion.ts`, `motionScope.ts` — движение и жизненный цикл анимаций.
- `src/onboarding/Onboarding.tsx` — компоновка, свайпы и переходы.
- `src/onboarding/CompletionScreen.tsx` — финальный экран.
- `src/guide/content.ts` — темы и шаги инструкции.
- `src/guide/GuideScreen.tsx` — поиск, оглавление и переходы по инструкции.
- `src/demo/MoreScreen.tsx` — демо размещения пункта «Инструкция».
- `INTEGRATION_PROMPT.md` — промпт для подключения; его копия в `src/demo/integrationPrompt.ts`.

Файлы в `docs/` содержат историю исследования и решений. При расхождениях источником текущего сценария служат `content.ts` и `scenes/index.ts`.

## Проверки и экспорт

```sh
npm run typecheck
npm test
npm run export:mobile
```

`export:mobile` создаёт JS/Hermes-бандлы и ассеты iOS/Android в `dist/`. Это **не** подписанные `.ipa` или `.apk`. Нативную сборку и подпись выполняют в окружении целевого приложения.

Не загружаются в Git: `node_modules`, `.expo`, `dist`, сгенерированные `ios/` и `android/`, локальные настройки окружения и ключи. Установка зависимостей выполняется через `npm ci`.
